# DEV-13 Document Metadata and Reading Order

一般向け文書から分離した、文書運用用の内部ガイドです。

## 1. 文書読解順（開発者向け）
- まず WRD-01 のコアテーマを読む。
- 次に NAR-10 / SYS-20 で体験設計と物語因果を合わせる。
- 実装時は DEV-10 / SYS-30（データ版）を参照して値・条件を確定する。
- アート実務は DEV-12 を参照する。

## 2. メタファー補助線
- エントロピーの凍結: 一切の変化と崩壊を許さない完全な静止
- 引力: 抗いがたい熱のうねり
- SSOT: 唯一の正本となるマスターデータ

## 3. 運用メモ
- 一般向け文書には数式・フラグID・実装参照索引を置かない。
- 開発者向け仕様は 90_For_Developers に集約する。
- SYS-30 は一般向けデータ版として維持し、実装ロジックの詳細は DEV-10 を正本とする。
- 一般向け文書のfrontmatterは表示用にHTMLコメント化し、冒頭で管理語彙を露出させない。
- 保護語彙の公開定義は WRD-02 を正本とし、公開文書ごとの独自再定義を避ける。
- 公開文書を更新する場合は DEV-11 を起点に逆引きを確定してから本文改稿する。

## 3.1 更新順（固定）

1. DEV-11: 公開記述と実装参照の対応行を更新する。
2. DEV-10: 条件式、遷移、フラグ定義の正本を更新する。
3. 公開文書（WRD-02 / SYS-20 / NAR-10 / WRD-01等）: 体験記述を更新する。

この順を崩す場合は、レビュー時に差戻し対象とする。

## 4. frontmatterコメント化運用（厳密版）

### 4.1 適用対象
- 公開文書: `README`, `WRD-01`, `NAR-10`, `SYS-20`, `SYS-30`, `ART-40`
- 目的: 非開発者の冒頭読解で管理語彙（uid/depends_on等）を見せないため。

### 4.2 例外
- 開発者向け文書（`90_For_Developers`配下）はfrontmatterを可視のまま保持してよい。
- 自動処理ツールがfrontmatter可視を要求する場合は、公開文書側ではHTMLコメントを維持し、別途メタデータ正本を開発文書に持つ。

### 4.3 文書追加時の必須チェック
1. 公開文書ならfrontmatterをHTMLコメント化したか。
2. 実装ID/フラグIDを本文へ直接記載していないか。
3. 実装参照が必要ならDEV-11に逆引き行を追加したか。
4. 計算式や条件を追加した場合はDEV-10へ正本追記したか。
5. 追加した相互リンクが有効か確認したか。
6. 保護語彙を追加・改稿した場合、WRD-02の【概念】【体験】【機能】3段を同時更新したか。

### 4.4 レビュー観点
- 読者分離: 非開発者文書が体験語彙中心で読めるか。
- 追跡可能性: 公開記述からDEV-11を経由してDEV-10へ到達できるか。
- 一貫性: 同一語彙が文書間で別意味になっていないか。
